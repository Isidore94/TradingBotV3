- [observed] 2026-09-18 — Source: TJ-1 reviewer rounds 2, 3 and 4 (`claude/tj1-day-review` @ 558b0f65 / 1a4fd1eb / 9d6b1b1a, `scripts/day_review_index.py:212-231`, `:245-262`, `:246-301`) — three facts about the Day Review per-session index, consolidated into one line 2026-09-20. (a) A (size, mtime) stamp is the wrong staleness test over an APPEND-ONLY store: `intraday_bounce_outcomes.csv` grows all day, so the index was thrown away on every M5 append (609 ms warm read -> 12,124 ms, 22 MB rewritten, nothing printed changed); a cache over an append-only log compares the appended TAIL against its scope, and a shrink or same-size change is a rewrite. (b) A cache-scope test built from three invented rows was green and never fired live: every recent session's index carries TODAY in scope because a windowed swing observation's `target_session` runs weeks forward (six live indexes 2026-08-28..2026-09-17 all held 2026-09-18, targets to 2026-10-01), so a staleness fixture is built from the real horizon CSV's target spread and scope is narrowed to (session, symbol). (c) The index is warm (about 500-820 ms) only when nothing is appending - its scope references 1,198 names for the next session, effectively the whole scanned universe, so during a session almost every M5 append rebuilds it (about 11 s, entirely on the read worker; Qt thread 0.20 ms). Clause (c) supersedes round 3's framing of "warm always"; accepted for TJ-1, the narrowing is an in-place swing-row update (TJ-2).
